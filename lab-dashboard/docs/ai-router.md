# 🧠 AI Router (สมองกลาง) — Design

- v1 อนุมัติ 2026-11-20 · แบบ B (ตัวคัดงานขนาดเล็ก + ตารางเส้นทาง + ตรวจโควตา)
- **v2 อนุมัติ 2026-11-21** · ให้คะแนนหลายมิติ + pace 5h/weekly + กระจายโหลดข้ามบัญชี + ระดับ ต่ำ/กลาง/สูง/สูงมาก + แตก subagent (แนวทางที่ 1)

## เป้าหมาย
1. **ประหยัดที่สุดก่อน**: ใช้บัญชีรายเดือน (Google Antigravity ทุกบัญชี, Claude Pro) ก่อนเสมอ
   **DeepSeek ใช้เป็นอันดับสุดท้าย** เพราะคิดเงินตามจริง
2. **ภายใต้ข้อ 1** เลือกโมเดลและระดับ effort ที่เหมาะกับงาน; ใช้โควตาที่ "จะทิ้งเปล่า" ให้คุ้ม และถนอมโควตาที่ใช้เร็วเกินงบ
3. กระจายงานระหว่างบัญชี ไม่ให้หนักไปบัญชีเดียว
4. ใช้ได้ทั้ง **หน้าแชท** (`🧠 Auto`) และ **งาน Cron** (`aiModel: "auto"`)

## ขั้นตอน
```
งาน → ① คัดงาน v2 → ② แคตตาล็อกโมเดล → ③ pace + ให้คะแนน (โมเดล×บัญชี×effort) → ④ แผน subagent → ⑤ รัน + failover
```

### ① คัดงาน (`classifyTask`, v2)
- **ทางลัด:** ข้อความ ≤ 20 ตัวอักษร หรือคำทักทาย ≤ 40 ตัวอักษร (ไม่มีคำเกี่ยวกับโค้ด) → `quick`
- นอกนั้น `gemini-3.8-flash-low` (บัญชีที่ pool gemini เหลือมากสุด) ตอบ JSON:
  `{type, complexity 0–100, risk 0–100, needs_tools, parallelizable, subtasks 0–6, reason}`
- **ระดับ (tier)** จาก `complexity + 0.25×risk (+5 ถ้าเป็นงานโค้ดที่ใช้เครื่องมือ)`:
  < 35 **ต่ำ** · < 60 **กลาง** · < 82 **สูง** · ที่เหลือ **สูงมาก**
- cache ตาม hash ของข้อความ 2 ชม. · ใช้เวลา ~7–8 วินาที (วัด 2026-11-21) · ล้มเหลว → ค่ากลาง (ยาก 55)
- **แท็กกำหนดเองในข้อความ:** `#ต่ำ #กลาง #สูง #สูงมาก` บังคับระดับ · `#ประหยัด/#ถนอม` หรือ `#เต็มที่/#ฟุ่มเฟือย` บังคับโหมดงบ

### ③ Budget & Pace Engine + ให้คะแนน (`buildCandidates`)
**pace ต่อหน้าต่างโควตา:** `surplus = %เหลือ − %เวลาที่เหลือก่อนรีเซ็ต`
- **แหล่งโควตา agy = `agy -p /usage`** (ต่อบัญชีด้วย `HOME=…`, cache 60 วินาที, ~4 วินาที) — ตรงกับหน้า "View Usage" ของแอป
  API `retrieveUserQuotaSummary` / `retrieveUserQuota` ส่งมาแค่กลุ่ม Claude & GPT และ Gemini 5h ไม่มี Gemini weekly กับ Argon (ตรวจ 2026-11-21)
- pool `gemini` (Flash / Hydrogen / Neon): **5h + weekly** · pool `claude` (Claude/GPT บน agy): **5h + weekly** · pool `argon`: **weekly อย่างเดียว** · Claude Pro: **5h + weekly**
- **รอบ 5 ชม. เหลือ < 15%** → **🟡 ถนอม** ทั้ง pool (รอบ 5 ชม. ที่ใช้เร็วกว่างบแต่ยังเหลือ ≥ 15% ไม่นับเป็นข้อจำกัด และไม่ถูกนำมาหักคะแนน — ให้รอบรายสัปดาห์ตัดสิน · ปรับ 2026-11-21 ตามที่บังยีขอ)
- รอบรายสัปดาห์ surplus < −0.15 (ใช้เร็วเกินงบและอีกนานกว่าจะรีเซ็ต) → **🟡 ถนอม** ทั้ง pool
- ไม่มีหน้าต่างไหนเกินงบ และมีหน้าต่างที่ surplus ≥ +0.2 **หรือ** เหลือเวลา < 20% ของรอบแต่ยังเหลือ ≥ 30% → **🟢 ฟุ่มเฟือยได้**
- นอกนั้น **🔵 ปกติ** · หน้าต่างที่ยังไม่เริ่มนับ (100% ไม่มีเวลารีเซ็ต) ไม่นับเป็นข้อจำกัด

**effort ที่ใช้จริง** = ระดับงาน ±1 ตามโหมด (ฟุ่มเฟือย +1, ถนอม −1)

**คะแนน** ของแต่ละ (โมเดล × บัญชี):
```
0.5×คุณภาพ  + 30×surplus  (−15 ถ้าเหลือ < 20%)
− 4×(คุณภาพที่ขาดจากเป้าของระดับ)           ← อ่อนเกินงาน
− 0.6×(คุณภาพที่เกินเป้า)×ต้นทุน×ความเข้มงบ   ← เปลืองเกินงาน (ถนอม ×2.2, ฟุ่มเฟือย ×0.25)
− 4×(งานที่ส่งเข้า pool เดียวกันใน 30 นาที, สูงสุด 4)   ← load balance
+ 6 ถ้าเป็นบัญชีเดียวกับที่ห้องแชทใช้อยู่               ← ไม่สลับบัญชีพร่ำเพรื่อ
```
เป้าคุณภาพตามระดับ: ต่ำ 72 · กลาง 84 · สูง 91 · สูงมาก 96 · ตัวที่เหลือ ≤ 5% หรือติด cooldown ถูกตัด
ผู้สมัคร subscription เรียงตามคะแนน แล้วต่อท้ายด้วย DeepSeek

### ④ แผน Subagent (แนวทางที่ 1: แตกทีมภายในงานเดียว)
- เงื่อนไข: `parallelizable` + ประเภท code/analysis + (ยาก ≥ 40 หรือ ≥ 3 ส่วนย่อย) + ไม่ใช่ DeepSeek
- จำนวน ≤ ส่วนย่อย และไม่เกิน ฟุ่มเฟือย 4 / ปกติ 3 / ถนอม 2
- โมเดลของ subagent (agy `invoke_subagent`): ถนอม `flash_lite` · ปกติ `flash` · ฟุ่มเฟือย + ยาก ≥ 80 → `pro`
- คำสั่งถูกแนบหน้าพรอมต์ที่ส่งให้ CLI เท่านั้น **ไม่ถูกบันทึกลงประวัติแชท**
  - agy: ใช้ `invoke_subagent` · Claude Code: ใช้ Agent/Task tool
  - กติกา: subagent ทำงานอ่าน/ค้น/ตรวจ; ถ้าต้องแก้ไฟล์ต้องแบ่งคนละไฟล์; ตัวหลักรวมผลและตอบเป็นภาษาไทย
- ทดสอบจริง 2026-11-21: agy เรียก `invoke_subagent` 2 ตัว (flash_lite) ทำขนาน แล้วสรุปรวมได้ถูกต้อง

### ⑤ รัน + ส่งต่อ (failover)
- **แชท:** รันผู้สมัครตัวแรก ถ้าพังด้วยเหตุโควตา/สิทธิ์ **และยังไม่ได้ใช้เครื่องมือ** → ข้ามทั้งกลุ่มที่พัง (บัญชี/pool เดียวกัน) ไปตัวถัดไป (สูงสุด 4 ครั้ง); agy แครชจาก RAM cache เสีย → ล้าง cache แล้วลองซ้ำ 1 ครั้ง; ถ้าเริ่มใช้เครื่องมือไปแล้ว → หยุดและแจ้งผู้ใช้
- **Cron:** `cron-ai-runner.py` เรียก `POST /api/ai-router/route` แล้วไล่ลองตามรายชื่อ (agy / claude CLI / DeepSeek API ไม่มีเครื่องมือ); router ล่ม → `gemini-3.8-flash-low`; cron ไม่ใช้แผน subagent

| 🔴 ประหยัดสุด | 5h < 8% · หรือ weekly surplus < −0.35 · หรือเหลือ < 8% | −2 | ×4 (−10 คะแนน) | ไม่แตก |

### เกณฑ์เปิดใช้งานอัตโนมัติ
- **งานง่าย–กลาง (< 65):** รัน **เอเยนต์เดี่ยว (Single Smart Pick)** เพื่อความเร็วสูงสุด (ไม่เสีย overhead 3 ด่าน)
- **งานใหญ่ / ซับซ้อน (≥ 65):** เปิดใช้ **ทีม AI ข้ามค่าย** อัตโนมัติในหน้าแชท (`🧠 Auto`) เมื่อครบเงื่อนไข:

- **แท็กสั่งบังคับ:**
  - `#ทีมข้ามค่าย` / `#ข้ามค่าย` / `#cross-team` / `#team` — บังคับเปิดทีม 3 ด่านแม้คะแนน < 65

   - **Fallback หลัก (ตามคำสั่งบังยี):** **Gemini 4 Neon (High/XHigh)** (ไม่ใช้ Hydrogen เป็น fallback หลักแล้ว)
   - Claude Code บังคับ `--permission-mode plan --disallowed-tools Edit,Write,NotebookEdit --no-session-persistence`
   - สำรวจโค้ดแล้วส่งพิมพ์เขียว JSON (1–4 ข้อย่อย พร้อม `model`, `access: read|write`, `files`, `depends_on`, `instructions`)
   - หากเป็นคำถามที่ไม่ต้องให้ Worker ลงมือ (`direct_answer: true`) ตอบจบได้ทันทีโดยไม่เสียรอบ Stage 2–3
2. **⚡ ด่าน 2: Workers (Gemini `Neon / Hydrogen / Flash / Argon` กระจายข้าม G1 + G2)**
   - จัดลำดับผู้สมัครตามรุ่นที่ Architect ขอ (`buildWorkerCandidates`) โดยกระจายโหลดข้ามบัญชี Google#1 และ Google#2 อัตโนมัติ
   - **Conflict-Free Scheduler (`tasksConflict` + `runWorkerWave`):**
     - งาน `read` ทั้งคู่ หรือ `write` ที่อยู่ **คนละไฟล์ชัดเจน** (canonical path ไม่ซ้อนทับกัน) → **รันขนานพร้อมกันข้าม G1 + G2**
     - งาน `write` ที่แตะไฟล์/โฟลเดอร์เดียวกัน, งาน `write` ที่ไม่ระบุรายชื่อไฟล์ (`files: []`), หรือ `read` ที่ทับไฟล์ที่กำลัง `write` → **ล็อกรันเรียงตามคิว 100%** กันไฟล์ตีกันพัง
     - ตัดวงจร dependency อัตโนมัติ (`breakDependencyCycles`) กัน deadlock
   - หาก Worker ขัดข้องก่อนใช้เครื่องมือ (`stepsCount === 0`) หรือเป็นงาน read-only → สลับบัญชี/รุ่นอัตโนมัติ (พร้อม crash-heal `agy`); ถ้าแก้ไฟล์ไปแล้วกลางทางจะหยุดปลอดภัยแล้วส่ง diff ให้ Reviewer ตัดสิน
3. **🔍 ด่าน 3: Reviewer (Strict Read-Only + รอบแก้ไขสูงสุด 1 รอบ)**
   - **ตัวหลัก:** Claude Opus · **Fallback หลัก:** **Gemini 4 Neon (High/XHigh)**
   - ตรวจรายงานจาก Workers + `git diff` (หรือรายการไฟล์ที่เปลี่ยนแปลงบนดิสก์นอก git repo) + อ่านไฟล์จริงเทียบเกณฑ์ผ่านงาน
   - ถ้าพบบั๊กร้ายแรงในโหมด `exec` → ส่ง `[[VERDICT:REWORK]]` เพื่อสั่งทีม Gemini แก้ไขได้สูงสุด **1 รอบ** แล้วตรวจปิดงานรอบสุดท้าย
   - ถ้าผ่าน (`[[VERDICT:PASS]]`) → สรุปคำตอบฉบับสมบูรณ์ภาษาไทยส่งถึงบังยีโดยตรง

### Fallback ใน `cron-ai-runner.py`
- หาก Dashboard AI Router API ติดต่อไม่ได้ `build_local_fallback_candidates(min_level)` ใช้ **Gemini 4 Neon** (`gemini-4-neon-medium` สำหรับงานปกติ, `gemini-4-neon-high` สำหรับ hard alert `min_level >= 2`) เป็นตัวสำรองหลักแทน Hydrogen แล้วเช่นกัน
