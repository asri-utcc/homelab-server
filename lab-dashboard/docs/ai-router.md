# 🧠 AI Router (สมองกลาง) — Design

- v1 อนุมัติ 2026-11-20 · แบบ B (ตัวคัดงานขนาดเล็ก + ตารางเส้นทาง + ตรวจโควตา)
- **v2 อนุมัติ 2026-11-21** · ให้คะแนนหลายมิติ + pace 5h/weekly + กระจายโหลดข้ามบัญชี + ระดับ ต่ำ/กลาง/สูง/สูงมาก + แตก subagent (แนวทางที่ 1)

## เป้าหมาย
1. **ประหยัดที่สุดก่อน**: ใช้บัญชีรายเดือน (Google Antigravity ทุกบัญชี, Claude Pro) ก่อนเสมอ
   **DeepSeek ใช้เป็นอันดับสุดท้าย** เพราะคิดเงินตามจริง
2. **ภายใต้ข้อ 1** เลือกโมเดลและระดับ effort ที่เหมาะกับงาน; ใช้โควตาที่ "จะทิ้งเปล่า" ให้คุ้ม และถนอมโควตาที่ใช้เร็วเกินงบ
3. กระจายงานระหว่างบัญชี ไม่ให้หนักไปบัญชีเดียว
4. ใช้ได้ทั้ง **หน้าแชท** (`🧠 Auto`) และ **งาน Cron** (`aiModel: "auto"`)

## ขั้นตอน
```
งาน → ① คัดงาน v2 → ② แคตตาล็อกโมเดล → ③ pace + ให้คะแนน (โมเดล×บัญชี×effort) → ④ แผน subagent → ⑤ รัน + failover
```

### ① คัดงาน (`classifyTask`, **v4** — 2026-11-22) · โค้ด: `difficulty-estimator.js` + `ai-router.js`
```
ข้อความ → [0] "ทำต่อเลย" ล้วนๆ? → สืบทอดจากงานก่อนหน้า (ไม่เรียก AI)
        → [1] ทางลัด (ทักทาย/สั้นมากที่ห้องยังไม่มีประวัติ)
        → [2] ตัวคัดงาน Flash Low + rubric + บริบทแชท → คะแนนจาก AI
        → [3] ผสมกับตัวช่วยตรวจจากข้อความ + prior ของห้อง → complexity สุดท้าย → ระดับ (tier)
```
**[2] rubric แยกมิติ** — AI ตอบเป็นจำนวนเต็มหยาบๆ ตามสเกลที่นิยามไว้ ไม่ใช่เลข 0–100 ตามความรู้สึก แล้วโค้ดคำนวณคะแนนเอง:

| มิติ | สเกล 0–4 (ตัวอย่างความหมาย) |
|---|---|
| scope | 0 ตอบอย่างเดียว · 1 จุดเล็ก · 2 หนึ่งไฟล์/ฟีเจอร์ · 3 หลายไฟล์ · 4 ระบบใหม่/ข้ามระบบ |
| depth | 0 ค้นดู · 1 งานประจำ · 2 ต้องตัดสินใจออกแบบ · 3 ไล่บั๊ก/แลกเปลี่ยนหลายทาง · 4 งานวิจัย |
| unknowns | สิ่งที่ต้องสำรวจก่อนลงมือ (0 ไม่มี → 4 ต้องไล่ทั้งระบบ) |
| steps | ขั้นตอนเครื่องมือที่คาดไว้ (0 ไม่มี · 1 = 1–3 · 2 = 4–10 · 3 = 11–30 · 4 = 30+) |
| risk | ความเสียหายถ้าพลาด (0 ไม่มี → 4 บริการหลัก/รหัสผ่าน/เงิน) |
| quality_bar | 0 ปกติ · 1 ขอความรอบคอบ · 2 ขอให้ตรวจซ้ำทุกอย่าง |
| human_minutes | เวลาที่ผู้เชี่ยวชาญที่รู้จักระบบใช้จริง (นาที) |
| parallel · depends_on_previous · type · needs_tools | จำนวนส่วนอิสระ · พึ่งบริบทก่อนหน้าไหม · ชนิดงาน · ต้องใช้เครื่องมือไหม |

prompt มี **ตัวอย่างอ้างอิง 6 ข้อที่มีคะแนนกำกับ** (ต่ำ→สูง) และคำเตือนให้ประเมินตามจริง (ห้ามขยาย แต่ห้ามต่ำเกิน)

```
dimScore  = (scope×1.0 + depth×1.2 + unknowns×0.8 + steps×1.0) / 16 × 100
timeScore = ตารางเวลา→คะแนน แบบสเกล log2:  1น.→5 · 5→20 · 15→35 · 30→45 · 1ชม.→58 · 2→70 · 4→80 · 8→90 · 16ชม.→98
คะแนน AI  = 0.5×dimScore + 0.5×timeScore            (ไม่มี human_minutes → dimScore อย่างเดียว)
```
**[3] ผสม** (`combine`):
- **ตัวช่วยตรวจจากข้อความ** (ทันที ไม่เสียโควตา): ความยาว · จำนวนไฟล์ที่พูดถึง · รายการหลายข้อ · คำบอกขอบเขต ("ทั้งระบบ", "สร้างหน้า", "refactor") · คำเสี่ยง ("restart", "ลบ", "production") · คำขอความรอบคอบ
  - ใช้ได้ **2 ทางเท่านั้น**: ดันคะแนนขึ้นเมื่อสูงกว่า AI (`+0.35×ส่วนต่าง`) และเป็น **พื้นขั้นต่ำ** เมื่อมีหลักฐานแข็ง (≥3 ไฟล์ → 50 · "ทั้งระบบ"/สร้างระบบ + ข้อความยาว → 60 · รายการ ≥4 ข้อ → 50)
  - **ห้ามดึงคะแนนของ AI ลง** — วัดแล้วพบว่าตัวช่วยตรวจมีสเกลต่ำกว่า AI เสมอสำหรับงานสั้นแต่ยาก (c17: AI 75 แต่ตัวช่วยตรวจ 36 → เฉลี่ยแล้วเหลือ 67) ผมลองเฉลี่ยในเวอร์ชันแรก (v4.0) แล้วถอยหลัง จึงเลิก
  - ข้อความสั้นมาก (≤25 ตัวอักษร ไม่มีคำสั่งลงมือ/ไฟล์) → ไม่เกิน 20
- **risk** = max(AI, 0.7×ตัวช่วยตรวจ) · **ระดับ (tier)** = `complexity + 0.25×risk (+5 งานโค้ดที่ใช้เครื่องมือ) (+3×quality_bar)` → < 35 ต่ำ · < 60 กลาง · < 82 สูง · ที่เหลือสูงมาก (เกณฑ์เดิมของ v3)

**บริบทแชท** (แก้จุดอ่อนที่ log จริงเจอ: "เริ่มทำงานได้เลย" ของงานสร้างระบบทั้งระบบเคยได้ 25/100):
- ข้อความ ≤300 ตัวอักษร ส่งบริบทแชท 3 คู่ล่าสุดให้ตัวคัดงานด้วย (ตัดป้าย 🧠 Auto ออก) + ข้อเท็จจริงของงานก่อนหน้า ("ใช้เครื่องมือ 14 ขั้น 9 นาที" — ไม่ส่ง *คะแนน* ให้ AI เห็น เพราะงานวิจัยพบว่าคะแนนก่อนหน้าทำให้ผู้ตัดสินเอนเอียง)
- **"ทำต่อเลย/ลุยเลย/ตามนั้น" ล้วนๆ** → สืบทอด 92% ของความยากงานก่อนหน้า โดยไม่เรียก AI (1–2 วินาที)
- **ข้อความที่พึ่งบริบท** (AI ตอบ `depends_on_previous=true`, เช่น "เอาแบบที่ 2 เลยครับ") → ความยาก ≥ 85% ของงานก่อนหน้า
- **ทางลัดข้อความสั้น ≤20 ตัวอักษรใช้เฉพาะห้องที่ยังไม่มีประวัติ** (พบจากชุดทดสอบ: "เอาแบบที่ 2 เลยครับ" เคยถูกตัดเป็น 5/100 ก่อนได้ดูบริบท) คำทักทาย/ขอบคุณยังลัดเสมอ
- prior ของห้อง = งานสำคัญล่าสุด 3 งาน ถ่วงลดลง ×0.92 ต่อลำดับ · TTL 8 ชม. · กู้คืนจาก `ai-router-log.jsonl` ได้หลังรีสตาร์ต

**วงจรป้อนกลับ** (ตอนงานจบ `noteOutcome` → `~/.gemini/ai-router-outcomes.jsonl`):
- ความยากที่สังเกตได้ = max(คะแนนจากจำนวนขั้นตอน [0→10 · ≤3→30 · ≤10→50 · ≤25→70 · มากกว่า→85], 0.9×คะแนนจากเวลา [<30วิ→10 · <2น.→30 · <5น.→50 · <15น.→70 · มากกว่า→85])
  แล้ว `prior = max(ที่ทำนาย, ที่สังเกตได้)` → งานที่ทำนายต่ำแต่ใช้เครื่องมือเป็นสิบขั้น จะทำให้ "ทำต่อเลย" ถัดไปสืบทอดค่าสูงตามจริง
- งานที่ถูกยกเลิก/ไม่ได้ทำงานจริงไม่นับ
- **`GET /api/ai-router/calibration`**: ต่อระดับที่ทำนาย → ขั้นตอน/เวลา/ความยากที่สังเกตได้จริงโดยเฉลี่ย, อัตราทำนายต่ำเกิน/สูงเกิน พร้อมตัวอย่าง
  ใช้ปรับเกณฑ์ **ด้วยมือ** (ไม่ปรับอัตโนมัติ — ต้องมีตัวอย่างหลักสิบขึ้นไปจึงน่าเชื่อถือ; ขณะเขียนเอกสารนี้ยังไม่มีข้อมูลสะสม)

**log** (`ai-router-log.jsonl`) บันทึกทุกมิติ: rubric รายมิติ · คะแนน AI (`llm`) · คะแนนตัวช่วยตรวจ · เวลามนุษย์ที่ประเมิน · สถานะต่อเนื่อง — ใช้ดูว่ามิติไหนแกว่ง

- cache ผลดิบของ AI 2 ชม. (key = เวอร์ชัน + โมเดล + ข้อความ + บริบท) แต่คะแนนสุดท้ายคำนวณใหม่ทุกครั้ง · ตัวคัดงานใช้ ~6.3 วินาที
- **แท็กกำหนดเองในข้อความ:** `#ต่ำ #กลาง #สูง #สูงมาก` บังคับระดับ · `#ประหยัดสุด #ประหยัด #ฟุ่มเฟือย #เต็มที่` บังคับโหมดงบ · `#ทีมข้ามค่าย` / `#เดี่ยว`
- ป้ายผลจัดระดับแสดงเวลามนุษย์และสถานะต่อเนื่อง เช่น `ยาก 40/100 ↩ต่อเนื่อง` · `ยาก 43/100 (≈1.0 ชม.)`

**ข้อจำกัด / ความซื่อสัตย์ของตัวเลข:**
- เวอร์ชันแรก (v4.0) **ถอยหลังในงานยากข้อความเดียว** (เฉลี่ยตัวช่วยตรวจดึงคะแนนลง) — แก้แล้วใน v4.1; ชุด holdout ชุดแรกถูกเห็นผลไปแล้วจึงไม่เป็นอิสระ จึงเขียนชุดล็อกชุดใหม่ก่อนแก้
- ชุดล็อกพบบั๊กทางลัด ("เอาแบบที่ 2 เลยครับ" ได้ 5) → แก้แล้ว (ได้ 84) **หลังแก้ชุดนี้ไม่เป็นอิสระอีก** ใช้ตัวเลข "ก่อนแก้" เท่านั้น
- ชุดทดสอบเล็ก (40 ข้อ) ช่วงเฉลยเขียนเอง → ผลต่าง 1–2 ข้อไม่มีนัยสำคัญทางสถิติ; ที่ชัดเจนจริงคือข้อความต่อเนื่อง (0/4 → 4/4) และความห่างจากเฉลย
- AI ยังแกว่งบางข้อได้ถึง ~9 คะแนนระหว่างรอบ (c12, c20, c07) และ tier ใกล้ขอบเกณฑ์ (35/60/82) พลิกได้ — **เกณฑ์ทีมข้ามค่ายที่ 65 ก็เช่นกัน**: งานที่ได้ 63–67 อาจเปิด/ไม่เปิดสลับรอบกัน
- **Flash Medium เป็นตัวคัดงาน: ไม่ดีกว่า** (26/30) แต่ช้ากว่า 58% (10.0 vs 6.3 วินาที) → ใช้ Flash Low ต่อ (ตั้ง `AI_ROUTER_CLASSIFIER_MODEL` เพื่อเปลี่ยน)
- ความยากที่สังเกตได้จากจำนวนขั้นตอน/เวลา เป็นตัวแทนหยาบ ไม่ใช่ความยากจริง

**effort ที่ใช้จริง** = ระดับงาน ±1 ตามโหมด (ฟุ่มเฟือย +1, ถนอม −1)

**คะแนน** ของแต่ละ (โมเดล × บัญชี):
```
0.5×คุณภาพ  + 30×surplus  (−15 ถ้าเหลือ < 20%)
− 4×(คุณภาพที่ขาดจากเป้าของระดับ)           ← อ่อนเกินงาน
− 0.6×(คุณภาพที่เกินเป้า)×ต้นทุน×ความเข้มงบ   ← เปลืองเกินงาน (ถนอม ×2.2, ฟุ่มเฟือย ×0.25)

```
